# 单条记录与批量新增

```json
{
  "id": "term-id",
  "name": "隔离开关",
  "definition": "具有明显断开点的设备。",
  "scopes": [{"type":"global"},{"type":"app","id":"app-device"}],
  "status": "enabled",
  "recallCount": 320,
  "operator": "admin",
  "updatedAt": "2026-11-19T03:00:00Z"
}
```

一条记录只有一个词条文本和独立ID。表单字段为词条、释义、应用范围、状态；次数、操作人、时间由程序维护，表单不采集。`operator` 在本POC使用明确的示例身份；真实系统应由当前登录身份产生。

## 保存与冲突

新增界面支持增删多个普通输入行。空行不计入；至少一个词条、释义及应用范围必填。保存先完整校验，再为每个词条生成独立记录，共享本次释义、范围和状态。任何错误或冲突阻止整批写入。编辑仅允许当前一项，不能在一项写入顿号或换行组合。

比较采用全半角兼容、忽略大小写及空白的规范化文本。范围有交集时，同批和已有记录均不可重复；范围无交集允许相同文本。

## 列表与范围

列表按次数降序，同次数按更新时间降序。一行一条记录，所有内容为普通单元格，应用范围无链接。释义超过200个Unicode字符时截取前200字符加三个英文点；编辑始终保留完整释义。

应用范围可选全局及多个专业Agent。筛选采用并集，空选显示全部，全选明确包含全局和每个Agent；搜索不会改变全选定义。范围选择与表单复用组件，具体范围不可来自知识库。

Agent增强开关与词条启用状态共同决定有效配置；停用项排除，开关关闭返回空配置。相同文本存在全局与Agent配置时，选择Agent配置。该规则由 `effectiveEntries` 统一定义，不增加问答或查询演示界面。

## 单条变更记录

入口在当前行操作。弹层沿用既有样式，按 `termId` 精确过滤记录，不依赖文本。列表和变更记录的操作人统一为 `admin`，包括浏览器历史数据；编辑、停用和导入更新当前记录信息。

变更记录仅展示时间、操作、词条、应用范围和操作人，不提供修改记录的按钮或执行路径。表单不增加人员字段。

## 导入导出与转换

CSV仅四列：词条、释义、应用范围、状态。导入以顿号拆分词条单元格为空值过滤后的多个候选，逐条生成独立ID；导出每条记录一行。范围以 `|` 分隔，逗号和引号按CSV规范转义。全部行通过校验后写入，次数初始化为0。

历史浏览器数据和快照转换只保留当前定义的字段，旧额外维护字段不再存入当前模型。旧单范围转换为数组，已知历史知识库标识仅转换到原对应Agent，未知范围不会转为全局。已有合法次数保留，缺少次数的初始示例补入对应示例次数，自建记录默认为0。
